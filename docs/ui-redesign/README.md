# EyeCan Room UI 개편 검증

- 날짜: 2026-09-25
- 브랜치: `feat/eyecan-brand-ui-redesign`
- 비교 기준: `fc5d29e`
- 범위: 프론트엔드 브랜드, 화면 구성, 설정 분류, 피드백, 접근성, 반응형 배치.
- 변경하지 않은 영역: Python 시선 계산·학습·응급 판정, 카메라 방향 판정, Arduino 스케치·핀·시리얼 프로토콜.

## 공통 자산

- `apps/web/public/brand/eyecan.svg`: 열린 C 윤곽과 안쪽 획으로 만든 단색 심볼. favicon과 모든 `BrandLogo`가 같은 SVG 원본 사용.
- `BrandLogo`: 가로·세로·심볼 조합, 기본·밝은색·단색 표현. 홈 96px, 헤더 24~32px 심볼.
- `apps/web/public/fonts/PretendardVariable.woff2`: Pretendard v1.3.9, 로컬 제공. 같은 폴더의 `OFL.txt`에 SIL OFL 1.1 라이선스 포함.
- `styles/tokens.css`: 라이트·다크 색상, 폰트, 모서리, 작은 그림자 토큰.
- `styles/base.css`, `setup.css`, `room.css`, `radial.css`: 기본 요소와 화면별 스타일. 이전 중복 덮어쓰기 제거.
- 공통 버튼·상태 표시·오류·알림·연결 상세. 일반 아이콘은 lucide-react 사용.

## 동작 보존 및 UI 보완

- HOME → 눈동자 인식 → 외장 카메라 연결 → ROOM 순서 유지. 실제 준비 상태에 따라 진행하며 데모 진입 없음.
- 기기 선택은 기존 카메라 방향 판정과 깜빡임으로 실행. 영상만 180도 회전.
- 십자선·영점 상태·노브 표시 조건과 이동 반경, 시선 오차 배율 보존.
- 장치 로그는 연결 상세 팝오버 안에 배치. 로테이션 진입 시 팝오버 닫힘.
- 누적 회전 각도를 사용하여 마지막 → 첫 항목도 같은 방향으로 이동. 초기 배치와 회전 분리, 회전축을 중앙점으로 제한해 가로 스크롤 제거.
- 메뉴 항목의 크기는 활성 여부와 무관하게 고정. 각 설정 메뉴는 최대 6개.
- 선택 속도·화면·개인화·설치 점검 하위 메뉴 연결. 기존 모델·학습·모터 API와 명령 유지.
- 로컬 속도 설정이 재접속 시 서버 초기값으로 덮어써지지 않도록 보존.
- 장치 거부·전송 실패는 오류 아이콘과 문구로 표시. 성공은 물리 동작 완료가 아닌 "명령을 전달했습니다"로 표현.
- 응급 알림은 비점멸 모달로 표시하며 키보드 초점을 유지. 실제 외부 호출 미실행 문구 표시.

## 자동 검증

```bash
cd apps/web
pnpm exec tsc --noEmit --pretty false
pnpm build
pnpm test:ui
```

Chrome이 설치되어 있어야 합니다. Playwright가 4173 포트에 테스트용 Vite를 띄우며 실제 개발 서버 5173을 변경하지 않습니다.
`tests/fixture.ts`에서 카메라 영상, 시리얼 입출력, API, WebSocket을 모의 처리합니다. 앱 자체에 테스트 진입점이나 가짜 준비 상태는 추가하지 않았습니다.

최종 결과: 타입 검사·프로덕션 빌드 통과, Playwright 42개 테스트 통과.
반복 실행 중 로컬 부하로 설정 전체 탐색 1건이 기존 30초 제한을 초과하여, 테스트 제한을 60초로 변경하고 해당 항목을 재검증했습니다.

- 1440×900, 1280×800, 1024×768, 390×844, 360×800: 라이트·다크 총 10개 조합의 홈·준비·카메라·탐색·기기 메뉴·응급 화면 캡처.
- 주요 버튼 화면 내 배치, 4/5/6개 메뉴 겹침·가로 넘침, 모바일 모든 설정 하위 메뉴 및 글자 넘침 검사.
- 카메라 대기·얼굴 대기·기준점 대기·모델 오류·권한 거절·재시도·영상 단절과 재연결 검사.
- 기본 2초 회전, 1~5초 적용, 마지막 → 첫 항목의 누적 -360도, 취소 시 명령 미전송 검사.
- 테마·속도 새로고침 유지, 개인화 학습·저장·초기화 API 경로, 실패 시 오류 표시 검사.
- 커튼·조명·선풍기 전체 명령 시리얼 시퀀스 및 서버 로그, 거부·USB 단절·미지원 브라우저 피드백 검사.
- 모의 실제 각도 수신 → 500ms 대상 확정 → 깜빡임으로 메뉴 진입 → 깜빡임으로 명령 선택 검사.
- 시선 오차 좌표·반경 보존, 눈감음·얼굴 유실·보정·급변 제동·데드존에서 노브 숨김 검사.
- 응급 우선 표시·모달 초점·Escape 해제 방지·보조자 확인 해제 검사.
- CSS 200% 확대 및 reduced-motion에서 선택 버튼 접근 가능 확인. 이는 브라우저 실제 확대와 보조 기술 전 조합을 보증하는 검사는 아님.
- 라이트·다크 주요 글자/표면 토큰 대비 모두 4.5:1 이상. 라이트 보조 글자 5.89:1, 주요 버튼 6.38:1, 다크 보조 글자 8.19:1, 다크 버튼 8.89:1, 응급 흰 글자 6.57:1.

## 실기 확인 잔여 항목

- 실제 내장 카메라 얼굴 인식과 영점 준비, 외장 영상 인계.
- 실제 조도·복잡한 영상에서 십자선·메뉴 가독성.
- 실제 팬틸트 정지·이동 및 커튼·조명·선풍기의 물리 동작.
- 사용자의 실제 눈감음 선택·응급 제스처. UI 테스트는 서버 이벤트 수신 이후 경로만 검증.
- Safari/Firefox 실브라우저 및 OS 보조 기술 검증. 미지원 Serial 상태는 Chrome에서 API 미제공 모의 조건으로 검사.

실제 장치에 명령을 보내거나 펌웨어를 업로드하지 않았으며, 소프트웨어 검증 결과를 실기 완료로 취급하지 않습니다.
